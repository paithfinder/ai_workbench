# 自序 · 个人知识工作台需求与开发文档

> 文档类型：产品需求文档（PRD）与开发规格
> 当前版本：v1.1
> 更新日期：2026-08-14
> 产品定位：Evidence-first Personal Knowledge Workbench（可信知识炼化工作台）
> 当前工程基线：D1–D8 已交付；单用户、单预置知识空间

---

## 1. 产品定义

“自序”不是资料收藏夹、通用聊天机器人或自动写笔记工具，而是面向个人专业研究、学习和决策的可信知识炼化工作台。

核心链路：

```text
原始来源
→ 不可变版本
→ 可定位解析
→ AI 候选知识或用户直接知识
→ 用户审核
→ 正式知识与 Revision
→ 范围安全检索
→ 逐主张可信引用
→ 可审计回答、学习和训练反馈
```

产品的基本承诺：

1. 原始资料是证据，不能被 AI 输出替代。
2. AI 只能提出候选、研究结论和更新建议，不能直接写入正式知识。
3. 正式知识始终有明确身份：来源支持、用户原创或待验证。
4. 每次编辑创建 Revision；来源版本、引用与历史回答不因新内容静默漂移。
5. 检索、问答、出题、评分和学习建议均以同一知识与证据底座为依据。
6. 用户审批是任何正式知识新增、更新、合并或废弃的唯一写入边界。

## 2. 当前基线与版本目标

### 2.1 已交付能力（D1–D8）

| 能力 | 当前状态 |
|---|---|
| 来源导入 | PDF、Markdown、TXT、网页与粘贴文本的来源/版本导入基础链路已具备 |
| 解析与证据 | Docling 解析、版本化 Parse Artifact、Section、稳定定位与冻结引用已具备 |
| AI 提炼 | 结构化候选、Evidence 校验、提炼 Job 与可重试失败已具备 |
| 人工审核 | 候选编辑、接受、待验证、拒绝；接受事务创建正式知识、Evidence、复习卡和事件已具备 |
| 知识树 | `root/folder/document/point/source` 树、Revision、搜索、引用深链和键盘无障碍已具备 |
| 直接笔记导入 | 单/多 Markdown、TXT 或文件夹可直接创建正式 document 与 Revision；不创建 Source/Candidate、不解析、不调用 AI，导入后异步索引 |
| RAG | Keyword/Vector、范围过滤、Hybrid RRF、可选 Reranker、有界 Context、结构化回答与服务端 Citation Validation 已具备 |
| 评测 | 中文检索 seeds、检索评测与 QA 评测 runner 已具备 |

### 2.2 后续版本目标

| 阶段 | 目标 |
|---|---|
| P0：知识研究与更新 | 外部资料搜集、可信度判断、新旧知识影响分析、用户审批的 `KnowledgeUpdateProposal` |
| P1：长期学习 | FSRS 调度、学习任务、学习计划、提醒、掌握度与薄弱项分析 |
| P2：练习与考试 | 题目生成、文本/语音转写作答、基于知识证据的评分、成绩与专项补强 |
| P3：受控研究 Agent | 在前述领域能力稳定后，加入受控单 Agent 进行多步研究与 Proposal 生成 |

不以“多 Agent 数量”作为产品目标。可靠的证据、审批、Revision、检索与学习闭环优先于自动化程度。

## 3. 目标用户与核心价值

目标用户是长期管理专业知识、持续学习或需要基于资料做决策的个人用户。典型需求包括：

- 在 Obsidian 或本地先完成 Markdown 笔记，再选择直接纳入知识库或交给 AI 审查整合；
- 将网页、实时信息和权威资料固化为可追溯来源，而非停留在一次性搜索结果；
- 识别新资料对既有知识的支持、补充、冲突或过时影响；
- 在明确范围内获得带证据引用的回答；
- 将沉淀知识转化为计划、复习、练习和考试反馈；
- 看到自己在不同主题上的掌握变化与薄弱点。

| 用户问题 | 产品机制 | 结果 |
|---|---|---|
| 资料分散且难判断是否值得保留 | 来源固化、可信度评估、研究 Proposal | 资料变为可审查的候选资产 |
| 新旧内容可能冲突或过时 | 新旧 Revision/Evidence 比对与影响分析 | 用户知道哪些知识值得更新 |
| AI 结论不可信 | Evidence-first、服务端校验、用户审批 | 结论能回到具体来源版本和段落 |
| Markdown 笔记整理成本高 | 直接入库或 AI 审查整合二选一 | 用户可按资料成熟度选择路径 |
| 学完容易遗忘 | FSRS、计划、练习和复盘 | 知识进入持续训练闭环 |
| 考试或面试缺少针对性反馈 | 知识范围出题、证据评分、掌握度分析 | 获得可解释的补强建议 |

## 4. 核心领域对象与身份边界

| 对象 | 职责 | 是否可直接作为正式结论 |
|---|---|---:|
| `Source` / `SourceVersion` | 原始文件、网页或文本及其不可变版本 | 否；作为证据 |
| `ParseArtifact` / `Section` | 解析结构、稳定定位和冻结摘录 | 否；作为证据定位 |
| `ExtractionCandidate` | AI 从来源中提炼的知识建议 | 否 |
| `KnowledgeNode` / `KnowledgeRevision` | 用户确认后的正式知识与历史版本 | 是 |
| `KnowledgeEvidence` | 正式 Revision 与冻结来源证据的关系 | 不单独构成结论 |
| `KnowledgeUpdateProposal` | 新资料对现有知识的更新、补充、冲突或失效建议 | 否；必须审批 |
| `ReviewCard` / `ReviewLog` | 复习调度与反馈 | 否；训练记录 |
| `PracticeItem` / `Attempt` | 练习题、作答与评分记录 | 否；学习记录 |
| `Assessment` / `AssessmentAttempt` | 考试或面试卷、答案、分数和诊断 | 否；学习记录 |

### 4.1 正式写入规则

- 直接 Markdown 导入由用户显式发起，直接创建正式文档与 Revision；该内容必须清楚标注为用户导入/用户原创，不能伪装为来源支撑的 AI 结论。
- 经过来源提炼、外部研究或 Agent 分析产生的内容，只能进入 Candidate 或 Proposal。
- 用户点击接受/应用后，由领域服务在事务中创建新的 `KnowledgeRevision`、Evidence、ActivityEvent 和索引任务。
- Agent、前端和模型不能直接写数据库、对象存储、任意 Shell 或任意 SQL。

## 5. 用户流程

### 5.1 手动 Markdown 与图片附件导入

用户可选两条路径：

```text
Markdown/TXT（单个、多个或文件夹）
├─ 直接入库
│  └─ 创建正式 document/Revision → 异步建立检索索引
└─ AI 审查整合
   └─ 创建 Source/SourceVersion → 解析/提炼 → Candidate 审查 → 接受后入库
```

直接入库规则：

- 支持 `.md`、`.txt`；客户端和服务端共同限制扩展名、UTF-8、路径、层级和大小。
- 不创建来源、不进入解析队列、不调用 AI、不进入候选队列。
- 创建后的 document 可参与现有 Hybrid RAG；其直接导入身份在 UI 中清晰可见。
- 单个 Markdown 可携带关联图片：首期将图片作为 Markdown 附件资源保存并以稳定相对引用关联 Revision；图片 OCR、图片内容问答和跨文档媒体复用不属于首期范围。
- 选择 AI 审查整合时，Markdown 与图片作为来源版本保存，AI 只能产出需用户审核的候选。

### 5.2 多链接资料研究与知识更新

```text
全局悬浮搜索框 / 多 URL 输入
→ Provider 搜索或抓取权威、实时资料
→ 保存快照为不可变 SourceVersion
→ 解析与索引
→ RAG 召回现有知识、Revision 与来源
→ 比对支持、补充、冲突、过时和重复
→ 生成 KnowledgeUpdateProposal
→ 用户查看证据、编辑并批准/拒绝
→ 批准后创建新 Revision 并异步索引
```

资料搜集入口是跨页面的全局悬浮搜索框，但知识树内搜索仍保留为本地知识定位工具；二者职责不同，不互相替代。

外部搜索 Provider 首期可接入 Grok，用于发现实时或权威资料；Provider 只负责搜索/抓取候选，最终可信性取决于已固化来源、版本、解析内容与用户审批，而非搜索模型的口头判断。

### 5.3 `KnowledgeUpdateProposal` 审核

Proposal 至少包含：

- 目标 Knowledge Node 与当前 Revision；
- 建议动作：`create`、`revise`、`supersede`、`merge_suggestion`、`mark_review_recommended`；
- 建议标题、正文、标签、条件和例外；
- 新证据、既有支持证据、冲突或失效证据；
- 新旧差异、影响说明、可信度与不确定性；
- Agent/模型版本、工具调用摘要与生成时间；
- 状态：`draft`、`pending_review`、`approved`、`rejected`、`applied`、`superseded`。

用户可以批准、拒绝或编辑后批准。批准后不是覆盖正文，而是创建新 Revision；冲突内容默认保留并标注需要复核，不自动删除历史知识。

### 5.4 学习、练习与考试

```text
正式知识与 Revision
→ FSRS/确定性调度计算到期内容
→ 今日学习与学习计划
→ 复习、练习或考试
→ 记录答案、评分证据与结果
→ 更新掌握度、薄弱项和后续任务
```

- FSRS 调度、到期判断、间隔计算和成绩聚合属于确定性领域逻辑，不交给 Agent。
- Agent 可以根据学习目标、到期任务和薄弱项生成解释性计划，但不得擅自修改调度、成绩或正式知识。
- 练习支持选择、填空、简答和默写；题目必须绑定知识范围、目标 Revision 和生成版本。
- 考试支持由易到难的自定义题型，以及面试模式的自我介绍、基础问答、算法、项目深挖等题组。
- 首期作答支持文本和浏览器语音转文字；录音保存、实时面试音频分析和人格/情绪判断不在范围内。
- 评分以知识点要点、范围内 Evidence 和明确 rubric 为依据，不能只用字符串相似度；评分结果必须区分自动建议与用户确认成绩。

## 6. 功能需求

### 6.1 资料搜集与全局搜索

| 能力 | 要求 |
|---|---|
| 悬浮搜索 | 在工作台主界面可唤起；支持关键词、时间倾向和资料类型；不替代知识树内搜索 |
| 多 URL 输入 | 支持一次输入多个 HTTP/HTTPS URL，逐个展示抓取、解析和失败状态 |
| Provider 边界 | Grok/其他 Provider 的 Key 仅在服务端；请求、响应摘要、耗时和失败可审计 |
| 来源固化 | 每份最终采用的网页/文档形成 Source 与不可变 SourceVersion，保存 URL、抓取时间、内容 Hash、最终 URL 和必要响应元数据 |
| 安全 | 拒绝私网、环回、云元数据和危险重定向；限制超时、重定向和正文大小 |
| 可信度 | 输出证据覆盖、来源类型、时效性、冲突和不确定性；不得把模型置信度当作事实真相 |
| 入库边界 | 外部资料先形成来源和 Proposal，未审批不得修改正式知识 |

### 6.2 知识更新与影响分析

- 新来源或新 SourceVersion 完成解析后，可在用户发起时分析关联知识。
- 分析结果至少区分：支持现有结论、补充信息、矛盾、可能过时、重复、证据不足和无法判断。
- 影响分析在范围内使用 Hybrid RAG；检索过滤必须由数据库执行，不能只写入 Prompt。
- 建议更新必须有可定位的新旧 Evidence；找不到充分证据时输出“需要更多证据”，而非编造差异。
- 应用 Proposal 时保留此前 Revision、Evidence、审计记录和可回退路径。

### 6.3 知识库录入与维护

| 输入 | 路径 | 结果 |
|---|---|---|
| 单个 Markdown/TXT | 直接入库 | 正式 document/Revision，异步索引 |
| 多个 Markdown/TXT 或文件夹 | 直接入库 | 保留相对路径的目录树、正式 document/Revision，异步索引 |
| Markdown 与关联图片 | 直接入库或 AI 审查整合 | Revision 与附件资源稳定关联 |
| PDF、网页、粘贴文本 | 来源提炼 | SourceVersion、解析、Candidate、人工审核 |
| 多个网站链接 | 研究整合 | 多 SourceVersion、证据比对、Proposal、人工审核 |

知识树、Revision 编辑、搜索、来源引用和回收站继续使用现有边界。任何编辑都必须使用乐观锁与幂等键，避免并发覆盖或不确定响应重复写入。

### 6.4 可信问答

生产问答执行：

```text
Scope → Keyword/Vector → RRF → 可选 Rerank → Bounded Context
→ Structured Answer/Abstain → Citation Validation → Persistence
```

要求：

- 范围可选整个知识库、目录、文档或知识点；服务端按 `space_id + ltree` 强制过滤。
- 回答区分正式知识、根据来源归纳和未受当前知识库支持的通用补充。
- 每个事实性 Claim 必须关联本次 Context 中有效 Evidence；无证据、越范围或无效引用时安全拒答/失败关闭。
- QA Turn 保存问题、范围快照、检索命中、回答、引用、模型/Prompt/索引版本和失败状态。

### 6.5 长期学习

| 能力 | 要求 |
|---|---|
| 复习调度 | 用版本化 Scheduler Adapter 接入 FSRS；保留可解释的到期原因和完整日志 |
| 今日学习 | 综合到期卡、待审核 Proposal、进行中的练习和学习目标排序；用户可调整优先级 |
| 学习计划 | 基于目标、可用时间、范围、到期任务和薄弱项生成可编辑计划；计划是建议，不重写调度事实 |
| 掌握度 | 从复习反馈、练习与考试结果计算，必须保存计算版本和原始记录 |
| 提醒 | 首期仅应用内待办和可配置提醒；外部发送行为需显式授权 |

### 6.6 练习、考试与面试

| 能力 | 要求 |
|---|---|
| 题目生成 | 指定范围、题型、难度、数量和目标 Revision；结构化输出并保存题目版本 |
| 练习题型 | 选择、填空、简答、默写；每题绑定考查知识点和评分 rubric |
| 考试组卷 | 由易到难，可指定题型比例、时长与范围 |
| 面试模式 | 支持自我介绍、基础问答、算法、项目深挖等题组；首期仅文本或语音转写作答 |
| 评分 | 结合答案、rubric、范围知识与 Evidence 评分；无足够 Evidence 时标记人工复核 |
| 结果 | 保存成绩、逐题反馈、覆盖知识点、薄弱项和后续练习建议 |
| 安全 | 题目、评分与反馈不能修改正式知识；模型推断的掌握度需和原始答题记录分离 |

## 7. Agent 与 AI 使用边界

### 7.1 优先采用受控单 Agent

首期 Agent 是单个受控研究助手，而非多 Agent 平台。它只在资料研究、知识对比和 Proposal 生成等目标不完全可预先定义的场景工作。

允许的白名单工具：

- 搜索已注册的外部资料 Provider；
- 读取已授权的来源、版本与 Section；
- 在指定范围内搜索知识和读取 Evidence；
- 比较 Revision、SourceVersion 和已存在 Proposal；
- 创建草稿 Proposal。

明确禁止：

- 直接创建或覆盖 `KnowledgeRevision`；
- 接受 Candidate、应用 Proposal、删除来源或移动知识树；
- 任意数据库查询、任意 HTTP、Shell、文件写入或凭据访问；
- 超出用户授权范围读取资料；
- 未经确认触发外部发布、提醒或付费操作。

### 7.2 框架策略

核心领域逻辑采用项目内 Application Service 和明确数据库事务实现：来源、解析、Evidence、Revision、审批、索引、FSRS、出题记录、评分记录与审计均不交给 LangChain/LangGraph。

- 模型调用使用官方 SDK 与内部 AI Gateway。
- LangChain 可仅在临时 Loader、边缘 Provider 实验或非核心评测中局部评估。
- 当出现多轮工具调用、循环补证、暂停审批、长时间恢复和可观测执行图等真实复杂度时，才局部评估 LangGraph。
- LangGraph Checkpoint 仅保存执行状态，不能成为知识、审批或学习事实源。

## 8. 非功能与验收要求

### 8.1 数据可靠性

- SourceVersion、ParseArtifact、Evidence 和 KnowledgeRevision 可追溯且不静默覆盖。
- 所有写接口使用 Schema 校验、`Idempotency-Key`、乐观锁和统一错误 envelope。
- 异步索引、解析、提炼和研究任务使用 Job/Outbox，按至少一次执行设计。
- 重要动作写入 ActivityEvent；Proposal 应用另有审计记录。

### 8.2 安全与隐私

- API Key 只在服务端环境变量或 Secret Manager，不出现在浏览器、日志或 Prompt。
- 外部 URL、来源原文、Agent 工具结果和模型输出均视为不可信输入。
- 对网页抓取执行 SSRF、超时、大小和重定向防护。
- 用户可追溯、导出和删除个人来源、知识、问答、练习与评分数据；删除保留期和历史引用策略必须明确。

### 8.3 验收重点

1. 用户可直接导入 Markdown/TXT，并在不调用 AI 的情况下参与检索。
2. 用户可选择 AI 审查整合，且未经审核内容不进入正式知识。
3. 外部检索结果能被固化为版本化来源，而非只显示即时模型摘要。
4. 系统能为新旧证据生成可解释的 `KnowledgeUpdateProposal`。
5. Proposal 未批准前，正式知识 Revision 不发生改变；批准后生成可追溯新 Revision。
6. 任何问答、出题或评分均不能引用范围外或本次未提供的 Evidence。
7. FSRS/掌握度计算可重放、可解释，并能回到原始复习或答题记录。
8. Agent 不能绕过审批、范围和工具白名单。

## 9. 当前不做项

- 多用户协作、组织权限与配额；
- 自动批准或自动删除正式知识；
- 多 Agent 互相委派、开放式工具市场和任意 MCP 写操作；
- 实时音频面试分析、视频分析与高风险人格判断；
- 生产级云同步、高可用、灾备和模型密钥托管；
- 跨工作台通用搜索和 Coding 工作台的写代码能力。

---

## 10. 成功标准

“自序”的成功不是收集更多笔记或生成更多 AI 文本，而是让用户能稳定完成以下动作：

> 把可信资料固化为证据；让 AI 帮助发现差异和机会；由用户决定哪些内容成为或更新正式知识；再把这份知识用于有引用的问答、学习、练习和复盘。
